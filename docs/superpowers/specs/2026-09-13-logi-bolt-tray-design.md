# Logi Bolt Tray — дизайн

Дата: 2026-09-13

## Цель

Windows 10/11 трей-приложение, показывающее заряд устройств (мышь, клавиатура и т.д.), подключённых через Logitech Bolt receiver. Отдельная иконка в трее на каждое видимое устройство. Клик по иконке открывает окно с подробной информацией, настройками, кнопкой обновления и выходом из приложения.

Приложение работает автономно — не требует установленного Logi Options+ / G HUB, общается с ресивером напрямую по HID++ 2.0.

## Ограничения окружения

Разработка ведётся в macOS-окружении без доступа к Windows и без физического Bolt receiver под рукой. Сборку (`dotnet build` / `dotnet publish`), запуск и отладку HID++-обмена с реальным железом выполняет пользователь на своём Windows ПК. Протокольная часть (HID++ парсинг, таблица напряжение→процент) пишется по опубликованным полям протокола и покрывается unit-тестами, не зависящими от Windows API — но требует итерации по логам/ошибкам с реального устройства.

## Технологический стек

- .NET 8, C#
- WPF — главное окно и настройки
- WinForms `NotifyIcon` — иконки в трее (по одной на видимое устройство), используется наравне с WPF-хостом
- hidapi (нативная библиотека, P/Invoke) — низкоуровневый доступ к HID-устройствам. DLL x64 (и опционально x86) кладётся рядом с исполняемым файлом.
- Собственный минимальный клиент протокола HID++ 2.0 (без стороннего кода/библиотек, без зависимости от Logi Options+/G HUB)
- Хранение настроек — JSON-файл в `%AppData%\LogiBoltTray\config.json`

## Компоненты

### LogiBoltTray.Hid
Обёртка над hidapi: перечисление HID-устройств с VID `0x046D` (Logitech), фильтрация по PID Bolt receiver, отправка/приём HID++ отчётов (короткие 7-байтные и длинные 20-байтные репорты), hot-plug (появление/исчезновение receiver'а).

### LogiBoltTray.Protocol
HID++ 2.0 клиент поверх LogiBoltTray.Hid:
- Discovery корневой фичи (feature `0x0000`) → построение таблицы фич конкретного устройства.
- Чтение заряда: основной путь — фича `0x1000` (BatteryUnifiedLevelStatus); фолбэк — `0x1004` (UnifiedBattery) или `0x1001` (напряжение, конвертируется в процент через таблицу соответствия для Li-Po).
- Чтение имени и типа устройства (мышь / клавиатура / гарнитура / трекбол / другое) — используется для выбора глифа в иконке.
- Обработка нескольких устройств, подключённых к одному ресиверу (до 6 на Bolt).

### LogiBoltTray.App (WPF, точка входа)
- Фоновый таймер опроса всех устройств с настраиваемым интервалом.
- Реестр обнаруженных устройств (модель в памяти): имя, тип, текущий %, статус заряда/подключения, признак "видимо в трее".
- Управление автозапуском через `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
- Загрузка/сохранение настроек в JSON.

### Иконки в трее
- Одна `NotifyIcon` на каждое видимое устройство.
- Битмап рендерится на лету в зависимости от выбранного стиля и текущего процента/статуса.
- **Стили иконки (выбираются в Настройках, применяются ко всем иконкам сразу):**
  - **A** — крупное число (%), фон закрашен по порогу.
  - **B** — эмодзи-глиф устройства + маленький цветной бейдж-кружок в углу (без цифр на самой иконке).
  - **C** — пиктограмма батарейки с заливкой по уровню заряда (без цифр).
  - **D** — гибрид: маленький силуэт устройства сверху, число снизу, общий цвет по порогу.
- **Цветовые пороги** (применяются везде, где стиль использует цвет — фон/бейдж/заливка/текст):
  - `< 20%` — красный
  - `20–60%` — оранжевый
  - `> 60%` — зелёный
  - `= 100%` — фиолетовый
- Тултип при наведении: имя устройства, точный процент, статус (заряжается / подключено / нет ответа).
- Левый клик по любой иконке открывает общее главное окно.

### Главное окно (WPF)
- Список всех обнаруженных устройств: имя, тип, точный %, статус.
- Кнопка **«Обновить»** — форсирует внеочередной опрос всех устройств.
- Раздел **«Настройки»**:
  - Интервал опроса (настраиваемый, например от 15 сек до 30 мин).
  - Стиль иконки (A/B/C/D) с live-превью.
  - Показ/скрытие иконки по каждому устройству отдельно.
  - Автозапуск с Windows (вкл/выкл).
  - Уведомление о низком заряде (вкл/выкл + порог в процентах).
- Кнопка **«Закрыть»** — полный выход из приложения: завершает процесс и убирает все иконки из трея. Системный крестик окна ведёт себя так же (не сворачивает в трей, а закрывает приложение), поскольку трей-иконки — самостоятельный постоянный интерфейс, а не окно.

## Данные и обработка ошибок

- Таймер по интервалу опрашивает все известные устройства → обновляет модель → перерисовывает иконки и (если открыто) главное окно.
- Кнопка «Обновить» форсирует опрос немедленно, вне очереди таймера.
- При отключении receiver'а или устройства — соответствующая иконка убирается из трея, устройство помечается как отключённое.
- При появлении receiver'а/устройства — заново запускается discovery, создаётся иконка (если включён показ).
- При ошибке/таймауте чтения — в тултипе используется последнее известное значение с пометкой "устарело"; следующая попытка — на следующем цикле опроса.
- Уведомление о низком заряде срабатывает через `NotifyIcon.ShowBalloonTip` при пересечении порога сверху вниз (не повторяется на каждом цикле, пока устройство не зарядится выше порога и не разрядится снова).

## Сборка и проверка

Разработка идёт без доступа к Windows-машине и Bolt receiver'у. План проверки:
1. Протокольная логика (парсинг HID++ пакетов, таблица напряжение→процент, выбор фичи батареи) покрывается unit-тестами на чистых данных (без реального HID-устройства).
2. Пользователь собирает (`dotnet build` / `dotnet publish`) и запускает приложение на своём Windows ПК с реально подключённым Bolt receiver.
3. По результатам (логи, ошибки, реальные значения feature ID у конкретных устройств) вносятся правки в протокольный слой — итеративно.

## Значения по умолчанию

- Интервал опроса: 60 секунд.
- Стиль иконки: B (эмодзи устройства + цветной бейдж).
- Порог уведомления о низком заряде: 20%.
- Все обнаруженные устройства изначально видимы в трее.
- Автозапуск с Windows: выключен по умолчанию, включается вручную в Настройках.

## Вне рамок MVP (сознательно не делаем сейчас)
- Push-уведомления от ресивера о мгновенном изменении заряда (вместо периодического опроса) — можно добавить позже, если периодического опроса окажется недостаточно.
- Современные toast-уведомления (Action Center) вместо `ShowBalloonTip` — можно заменить позже без изменения архитектуры.
- Поддержка Unifying-ресиверов (не Bolt) — не запрошена, но протокол HID++ 2.0 общий, так что расширение не потребует переделки ядра.
